# ClipRelay

[官网与下载](https://cliprelay.zestybead3.chatgpt.site) · [版本发布](https://github.com/ffffhx/cliprelay/releases)

Mac、Windows 与 Android 手机在同一局域网内互传文本和截图的小工具。选中或截图即发，对方直接粘贴。

官网源码位于 `website/`，包含功能介绍、正式版下载及安装指引。站点通过 Sites 独立部署；向本仓库推送源码不会自动替换已上线的官网。

## 2026-10-26 界面更新

### 2026-10-27 AI 控制接口（Windows 0.4.3）

主要入口为 ProfilePilot CLI 的 `ppilot remote`，应用安装时提供接收和连接后台。AI 可以列出和连接服务中的设备，不必先打开视频窗口，也无需注册 MCP；指令通过已有设备证书和加密控制通道交给目标电脑执行，沿用内外网自动路由。双方都需要新版 Windows ClipRelay，目标端开启「允许被连接」；控制端从 ProfilePilot 的同一 CLI 安装入口更新工具及 Agent 指引。本轮没有实现 Mac／Android 的 AI 被控接口。

- 浏览器：目标端安装 ProfilePilot CLI，日常 Chrome 通过对应 Profile 的连接扩展接入。可列出 Profile 和标签页、管理可修改的独立 Profile，以及读取 DOM、按元素引用点击和填写。新建 Profile 的普通启动不会自动开启 Agent 连接；目录中的 `automationReady` 和原因说明配置情况，实际连接还会检查控制权。
- Electron：在目标端 ProfilePilot「本地应用」登记目标应用并准备调试连接后，使用返回的 `local-app:` ID 控制。接口使用登记的 Gateway 逻辑端口；无需将原始调试端口暴露到公网。
- Windows：列出当前交互桌面的窗口，读取 UI Automation 控件及支持的操作，执行按钮、输入、选择、展开、滚动。必要时可返回窗口截图并使用远端键鼠输入。锁屏、系统安全桌面和高权限窗口不在普通用户执行器的可控范围内；自绘控件是否可读取取决于应用。截图使用目标窗口捕获，部分硬件渲染窗口可能无法正常成像。

CLI 流程为 `ppilot remote devices --json` → `connect <设备ID> --json` → 使用返回的 `--session <会话ID>` 调用 `profiles/apps/windows`、`browser/window observe` 和 `action --params-file` → `disconnect`。运行 `ppilot remote --help` 查看完整参数。每次动作携带最新观察版本；结果不确定时先检查状态，同一请求 ID 仅用于查询原操作回执。截图保存到控制端文件并返回路径，上传文件路径则属于被控电脑。

CLI 命令退出后，应用后台继续保留有独立凭据的会话；默认闲置 300 秒释放，连接时可指定 60–1800 秒的租约。后续命令续期，后台心跳不会无限延长闲置时间，主动 disconnect 立即释放。目标端显示「ClipRelay AI 正在控制」托盘标识，可停止 AI；用户交还控制后需新建已结束的 AI 会话，浏览器接管遵守 ProfilePilot 的 handoff/resume 协议。应用重启后旧 CLI 会话失效；后台失联后目标端租约在 60 秒后失效。进程异常退出时可能仍需在 ProfilePilot 结束残留任务。

可选 MCP 入口仍为 `ai.ps1`，适用于只接收 MCP 工具的客户端；其会话随 MCP 连接关闭而释放，不影响 CLI 租约。需要时将命令设为系统 `powershell.exe`，参数为 `-NoProfile -STA -ExecutionPolicy Bypass -File C:\Users\你的用户名\AppData\Local\ClipRelay\ai.ps1`。例如在 Codex 中手动添加（CLI 使用不需要执行）：

```powershell
codex mcp add cliprelay -- C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\ClipRelay\ai.ps1"
```

本机验证覆盖多个独立 CLI 进程及 MCP → 本地管道 → 双向 TLS → 普通桌面用户执行器 → Windows 控件的填写、点击、截图、撤权与重复请求防护；也验证 CLI 凭据隔离、跨命令续接、闲置过期及主动断开。已安装 ProfilePilot 的 Profile 创建／重命名／删除和已登记 Electron 的 DOM 读取也经过实测。浏览器完整输入流程及两台异地电脑的端到端操作需在相应设备和 Profile 可用时验证。相关入口为 `windows/tests/ai-cli-leases.test.cjs`、`windows/tests/ai-control.test.cjs`、`windows/tests/automation-native.ps1`、`windows/tests/automation-profilepilot.py` 和 `network/inputfocus/automation_integration_test.go`；CLI 实链路测试额外设置 `CLIPRELAY_AUTOMATION_TEST_CLI` 为打包的 `profilepilot-cli.cjs` 路径。

## 工作原理

- 配对连接固定两端证书，使用双向 TLS 传输文本和图片。Windows 向 Android/Mac 的普通广播通过接收端长轮询 `/v1/relay` 完成；Android/Mac 主动发送使用 `/v1/clipboard`。
- 旧版兼容默认关闭。明确开启后才使用 HTTP `47632`（`/push`、`/push-image`）和旧版 mDNS 发现；Mac 的旧版 HTTP 只接收文本，配对连接可接收文本和 JPEG。
- Mac 按下 `Ctrl+Alt+G` 后，脚本模拟 `Cmd+C` 获取选中文本、恢复原剪贴板，再发送给对端。
- Windows 直接监听普通的 `Ctrl+C`：当前应用照常完成复制，ClipRelay 把新文本并行发送给所有启用的接收设备；若没有发生新复制，则发送剪贴板当前文本。
- Windows 按 `Ctrl+Alt+F12` 时，在内存中截取并编码所有显示器一次，再把同一份 JPEG 并行发送给所有启用设备；不打开截图界面、不写文件，也不改本机剪贴板。
- 对端收到后写入系统剪贴板并弹出通知，直接按 `Cmd+V` 或 `Ctrl+V` 即可粘贴。
- Windows 可维护最多 16 个广播目标；Mac 可保存 16 台配对电脑，每次选择一台收发。Android 在远控剪贴板面板中可主动收发，前台接收服务可接收配对广播。配对失败不会回退到旧版 HTTP。
- mDNS 声明包含随机设备 ID、显示名称、协议版本、平台、端口和认证状态，不包含访问密钥、剪贴板内容或历史记录。
- 原生 Android 默认使用“品牌 + 型号”作为发现名称（例如 `realme RMX5002` 或 `OnePlus PHK110`），并在 TXT 记录中分别声明 `brand` 和 `model`；设置页仍可覆盖成自定义名称。

在 macOS 上使用 Node.js 22.12 或更新版本、Xcode Command Line Tools 构建：

```bash
npm run setup:electron
npm run build:mac -- arm64  # Intel Mac 使用 x64
```

产物位于 `.tools/mac-electron/`，解压后将 `ClipRelay.app` 拖入「应用程序」，通过 Finder 打开。源码安装也可运行 `bash mac-bootstrap.sh`。

1. 首次切换时，先停用 Hammerspoon 配置中的 ClipRelay 并 Reload，释放监听端口和快捷键。保留原配置文件，Electron 会读取其中的标准配置常量，以及 `hs.settings` 保存的设备、密钥、设备 ID 和发现开关；不会修改其他 Hammerspoon 配置。
2. 为 ClipRelay 授予「辅助功能」权限（系统设置 → 隐私与安全性 → 辅助功能），用于 `Ctrl+Alt+G` 获取选中文本。
3. 菜单栏 `ClipRelay` →「配对电脑与安全收发…」，输入可访问的电脑 IP 或主机名，默认远控端口 `48789`。在电脑端打开待配对列表，核对与 Mac 相同的验证码后确认。配对时无需共享账户密码或复制私钥。
4. 选择已配对电脑。`Ctrl+Alt+G` 会发送选中文本并恢复旧的纯文本剪贴板；「发送当前剪贴板」可主动发送文本或 PNG 图片，失败会显示原因。
5. 电脑端添加本 Mac 为「配对加密」广播目标后，Mac 会自动接收该电脑的文本和 JPEG。Mac 不为此打开接收监听端口；暂停、切换或移除电脑会取消正在等待的连接。移除只清理本机记录，电脑端授权请在电脑的设备列表中撤销。
6. 只有需要连接旧客户端时，才明确选择「使用旧版目标收发（未加密）」并开启旧版兼容；旧版设备仍可通过扫描或手工地址选择。

新配置位于 `~/Library/Application Support/ClipRelay/config.json`；之后启动优先读取此文件。`peer`、`peerPort`、`peerToken`、`localPort` 和 `hotkey` 可用于手动配置，修改后重新打开 App。持续集成已验证双架构构建与下载产物；开发包尚未完成 Developer ID 签名或公证，本次按要求不做 Mac 真机安装、系统权限与串流验收。`init.lua` 保留为迁移对照与旧版回退文件。

Mac 配对身份和主机记录保存在 `~/Library/Application Support/ClipRelay/paired/state.json`。私钥使用 Electron 的系统密钥保护功能加密保存；钥匙串不可用时拒绝配对，不降级保存明文私钥。后续 TLS 连接在发出 HTTP 请求前核对电脑证书；证书改变会停止连接。接收日志只保存消息 ID、摘要和处理状态，最多 4096 条；写入时清理超过一小时的记录，回执丢失不会重新覆盖剪贴板。

包含被控端引擎与辅助组件的开发包提供菜单「允许其他设备连接这台 Mac…」，可启动、停止本机远程访问，并管理待确认请求和已配对设备。运行期间关闭设置窗口会保留后台服务；停止远程访问或退出 ClipRelay 会回收它启动的原生进程。新配对请求会触发后台提醒，菜单栏同时显示待确认数量；点击提醒打开当前请求列表，核对两端验证码并勾选确认后才能允许连接。「已配对设备」中的「撤销访问权限」会先停用设备、核对状态，再移除授权；未能确认撤销时会显示错误，已停用的设备不会自动恢复权限。

「打开 ClipRelay 时自动启动远程访问」默认关闭，只保存明确勾选的设置，下一次打开应用时生效。每次启动仍会检查屏幕录制与键鼠控制权限；权限不足时停止启动并显示状态。菜单「本机远程访问权限…」只读取权限，分别点击「前往授权」才请求对应权限；如果仍未授权，会打开相应的系统设置页，避免系统不再弹窗时没有后续入口。请开启 ClipRelay 的权限后返回重新检查；打开设置不代表已经允许。窗口关闭或应用退出会取消并回收尚未结束的权限命令，迟到的请求不会再打开设置；授权拒绝、超时和校验失败不会显示为已允许。引擎声明 `com.cliprelay.host-engine` 身份；[Intel 测试机上的完整应用屏幕授权提示](https://github.com/ffffhx/cliprelay/actions/runs/39020812312)已确认显示外层 ClipRelay，并可从提示进入含有 ClipRelay 条目的系统设置页；实际授权生效及用户安装环境仍待验收。

Windows 与 Mac 的原生主机新增版本观察：剪贴板没有变化时只返回版本；条件写入拒绝过期版本，同一成功请求丢失回执后重试不再覆盖内容。工作进程重启会生成新的版本标识。Windows 在剪贴板锁内比较版本并写入；Mac 在写入前检查 `changeCount`，但 AppKit 没有原子比较替换接口，仍存在系统并发写入的短暂竞态。这些接口已接入下述桌面自动同步。Electron 本机剪贴板同样没有经过验证的原子比较写入接口；写入前后检查能够拒绝已观察到的变化，不能保证消除所有系统并发写入竞态。

Windows 与 Mac 桌面控制端现支持按电脑开启双向剪贴板自动同步。在“配对电脑”页面勾选“与这台电脑自动同步剪贴板”，设置会为该配对电脑保存，默认关闭，重新配对后需重新开启。只在当前远控会话有新鲜画面、输入未暂停时同步新复制的文字与 PNG；开启、重连、解锁或恢复后先记录两端已有内容，不用旧内容覆盖另一端。文件、空剪贴板和清空操作不自动传播。暂停收发、断开、锁屏、休眠和退出时停止自动操作。

两端内容同时变化会提示冲突并暂停；无法确认一次远端写入是否成功时也暂停，不自动重发覆盖。可用“发送当前剪贴板”或“取回电脑剪贴板”选择所需内容，再点“继续同步”。取回按钮在自动同步关闭时仍可使用；等待期间切换电脑、关闭或刷新设置窗口、锁屏，或者本机又复制了内容，迟到的响应不会继续应用。图片按解码后的像素比较，避免 PNG 重新编码造成来回发送；应用收到的配对及旧版转发会重建同步基线。旧版主机不支持版本接口时提示更新，不降级为无条件自动写入。

[Windows 完整包验收](https://github.com/ffffhx/cliprelay/actions/runs/38941494389)通过 15 项真实 Electron 剪贴板场景；[Mac Apple Silicon 与 Intel 完整包验收](https://github.com/ffffhx/cliprelay/actions/runs/38942083768)各通过 16 项。新增检查包含原生主机组件与 Electron 双向交换透明 PNG、条件写入及迟到请求拒绝，以及生产同步控制器的基线、双向文字与图片、冲突恢复、锁屏取消和防止回传。Mac 每个完整包另保留 24 项原生主机组件场景，Windows 保留独立安装及配对回归。下载包源码、程序哈希与验收记录均已核对，见 `.tools/uu-parity/clipboard-sync-artifacts.json`。自动控制器测试使用真实系统剪贴板和受控的远端、会话状态；这些结果不等同于两台真实电脑串流中的整体验收。系统权限弹窗、真实锁屏、外网与用户界面验收仍单独跟踪，未替换本机安装或正式发布。

Mac 被控端的配置准备模块使用应用指定的私有目录，不改动 `HOME` 或已有 Sunshine 数据。配置、管理凭据和日志仅当前用户可读写；已有证书与配对记录保留，链接、过宽权限及损坏的身份记录会使准备失败。管理密码通过 Electron `safeStorage` 保存加密副本，钥匙串不可用时停止准备。应用打包验收会使用临时目录、测试加密提供者和包内真实引擎验证配置解析、日志写入与身份复用；这项检查不代表系统钥匙串或完整被控服务已经验收。

Mac 主动发送文本最多 1 MiB，PNG 最多 8 MiB、4096 × 4096 且不超过 600 万像素；接收 JPEG 最多 25 MiB、32768 单边且不超过 2400 万像素。配对电脑需可从 Mac 访问；开发分支已接入跨网配对界面与网络辅助组件，电脑控制电脑能力见后文。完整 Mac 被控端仍在开发中。

协议测试可运行 `node --test windows/tests/mac-pairing.test.cjs windows/tests/mac-paired-relay.test.cjs windows/tests/mac-controller.test.cjs windows/tests/mac-owned-window.test.cjs`（测试用 Go 生成临时证书）。`TestMacClientRealRelayAndDesktopWorker` 验证真实 Go mTLS 接口到 C# 模拟剪贴板 worker；`windows/tests/mac_sunshine_pairing.py` 在 Windows 上启动隔离 Sunshine 验证真实配对握手，关闭输入与托盘，退出时清理私钥和测试进程。这些测试不替代 macOS App 构建、钥匙串及系统剪贴板验收。

## Windows 端

支持 Windows 10/11 x64，安装包内含 Electron，后台继续使用系统自带的 Windows PowerShell 5.1。安装脚本会：

- 把客户端和配置写入 `%LOCALAPPDATA%\ClipRelay`；
- 注册当前用户登录自启；
- 为监听端口添加仅限“专用网络”的入站防火墙规则；
- 安装后立即启动，系统托盘出现 ClipRelay 图标即表示运行中；
- 左键点击托盘图标可打开深色“设备链路”控制台，查看并一键复制本机主机名（`.local`）或局域网 IP；
- 控制台集中显示本机监听状态、文本/截图快捷键及冲突状态、广播链路和最近一次传输结果；
- 左侧设备列表可直接开关每台目标，通过 `···` 编辑或移除设备；支持添加和扫描最多 16 个目标，名称、地址、端口和访问密钥独立配置；全部关闭时暂停发送，本机仍可接收；
- 支持修改本机监听端口、接收密钥、通知和开机自启，并可并行检测所有广播设备。

从完整离线包安装：解压整个 `ClipRelay-Windows-*.zip`，双击 `Install.cmd`。源码构建需要 Node.js 22.12 或更新版本、Go 1.26.7，以及已登录的 GitHub CLI。在同一个系统 PowerShell 5.1 会话中运行：

```powershell
npm run setup:electron
& .\scripts\resolve_windows_components.ps1 -OutputDirectory .tools\windows-components
& .\scripts\package_windows.ps1
```

`windows/components.json` 固定已验证的 Windows 播放器、桌面网络组件和修改版 Sunshine 构建。下载时核对构建成功状态、源码提交和文件摘要；构建产物过期时需重新构建、核验并更新固定版本，不会自动选取另一个版本。已有本地组件时，可向打包脚本分别传入 `-ViewerArtifact`、`-NetworkArtifact` 和 `-EngineArtifact` 目录。

完整包包含桌面主控、被控服务、网络组件、许可和引擎修改源码。安装器先校验整包，再停止旧应用；缺文件或摘要不一致时不会继续安装。升级保留原配置中的设备身份、配对目标、端口、兼容开关及其他设置。可在解压目录中先运行只读校验：

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\ClipRelay-Windows\install.ps1 -ValidateOnly
```

不支持只下载一个 `install.ps1` 或从未打包的源码目录直接安装。`Windows Complete Package` 工作流在一次性 Windows 机器上构建并验收，产生检查记录和 ZIP，不发布更新。

完整包已通过 [Windows CI 实际安装验收](https://github.com/ffffhx/cliprelay/actions/runs/38712007226)：验证 SYSTEM 服务管道、安装命令退出后的 Electron/后台/监听存活、默认关闭旧版接收，以及 Electron 退出后的后台管道清理。该验收不包含真实硬件串流、用户界面操作或公网远控；尚未替换开发电脑上的正式安装。

添加防火墙规则时会出现一次 UAC 确认。安装后添加配对设备，或在两端明确开启旧版兼容，正常按 `Ctrl+C` 即会同时复制
到本机并广播；按 `Ctrl+Alt+F12` 会静默广播整个虚拟桌面的 JPEG 截图。接收的文本或
截图会进入剪贴板。

配置保存在 `%LOCALAPPDATA%\ClipRelay\config.json`。左键点击托盘图标，或右键选择
`设置 / 配置对方设备...`：在“这台电脑”中切换本机主机名 (`.local`) 与局域网 IPv4，点击 `复制` 后发给对方；
左侧列表始终显示所有已保存设备，开关决定该设备是否接收广播，停用后仍留在列表中。点击 `+ 添加` 可手动添加，点击 `扫描添加设备` 可发现局域网目标并合并到列表；通过每行的 `··· → 编辑设备 / 移除设备` 管理名称、地址、端口和密钥，修改立即保存。检测连接只探测已启用设备，不会修改任何剪贴板。
“检测全链路连接”会先在后台扫描局域网，按设备 ID 更新已有目标的 IP 和端口并自动保存，再检测连接；不会自动新增目标，也不会改动名称、密钥或启用状态。未发现的设备仍按已保存地址检测，扫描失败时也会回退到已保存地址。
文本和截图发送遇到连接失败或超时时，会在允许局域网发现的情况下扫描一次（约 1.8 秒）；仅当同一设备 ID 的地址或端口发生变化时，保存新地址并重试一次。已成功设备不重发，密钥/HTTP 错误不重试；未发现新地址则保留失败结果。自动恢复要求设备已通过扫描关联到真实设备 ID，不能仅凭相同名称识别手动添加的设备。
在设置中可修改“局域网发现名称”或关闭“允许局域网发现”；这两项变化会在保存后重启后台服务。
广播时单台设备离线不会阻止其他设备接收；界面会显示“全部送达”“部分送达”或“全部失败”，并保留逐设备结果。
如果修改监听端口，ClipRelay 会申请更新专用网络防火墙规则并自动重启；这一步可能出现 UAC 确认。
设备列表中某个目标的访问密钥，需要与该目标自己的“接收密钥”一致；主窗口的“本机接收密钥”只保护发往这台 Windows 电脑的请求。留空则兼容未启用认证的旧客户端。
卸载命令：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File "$env:LOCALAPPDATA\ClipRelay\uninstall.ps1"
```

如只想从仓库临时运行，先准备 Electron，再通过独立启动脚本拉起（不运行安装器）：

```powershell
npm run build:windows
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass `
  -File .\windows\start.ps1 -OpenSettings -Peer 192.168.1.100
```

安装后的应用入口是 `%LOCALAPPDATA%\ClipRelay\desktop\ClipRelay.exe`；登录自启使用 `--background`。`start.ps1` 通过独立 helper 启动应用，终端退出后托盘和接收服务继续运行。Electron 与原后台通过随机命名管道通信；关闭设置窗口不退出后台，托盘「退出」会同时结束 Electron 与后台。

迁移回归：`npm run test:electron`；Windows 原生桥接和 HTML 交互测试分别运行 `windows/tests/run-electron-live.ps1`、`windows/tests/run-electron-live.ps1 -Mode renderer`（系统 PowerShell 5.1，`-STA`）。脚本独立启动隔离测试 App 并输出结果目录，最终查看其中 `test-results/results.json` 的 `complete: true`；截图也在该目录。测试配置使用独立端口，配置保存不会改动用户的开机快捷方式。

## Android 端（原生 APK）

Android 0.10.34 优化后台耗电：Android 13 及以下的设备发现只使用 Wi-Fi／以太网接口，离开电脑列表后关闭本次扫描的解析器和计时器；接收服务复用数据库连接，跳过不存在的旧版数据库。外网电脑状态在应用前台每约 3 秒更新，后台状态不变时逐步放缓到最多 30 秒；回到前台或网络变化会立即刷新，相同通知不再重复发布。配对确认、剪贴板长轮询和配对证书校验保持原有流程；后台电脑在线状态的显示可能有最多约 30 秒延迟。这些调整不改变画质、帧率或系统后台权限，实际续航收益仍需相同使用条件下对照测量。

停止接收时立即阻止后续投递，并在后台关闭 TLS 连接，避免 Android 因主线程执行网络关闭而导致应用退出。

原生工程位于 [`android-app/`](android-app/)，支持 Android 8.0 及以上版本。App 会运行一个
带常驻通知的前台接收服务，支持文本 `/push` 和截图 `/push-image`。收到内容后会：

- 将文本或截图写入手机系统剪贴板；
- 弹出可关闭内容预览的通知；
- 在 App 内保留最近 30 条文本与截图，点击进入无系统栏的沉浸式全屏，左右滑动切换；全屏图片支持 1×–5× 双指缩放与放大后拖动，拖到左右边缘后松手，再向外滑动可切换相邻的图片或文字；轻点内容可显示复制、关闭及横竖屏控制；
- 根据设置在手机重启或 App 更新后恢复接收。

文本全屏阅读默认渲染 Markdown，支持标题、列表、引用、表格、链接及带语法高亮的代码块。
预览保留原文中的单次换行，避免复制来的多行文字被合并为同一段连续文字。
独立段落间留一行空白；连续列表项紧凑排列，原文在列表项间留有空行时使用较大间距，嵌套列表分别判断。
预览字号旁可切换深色（黑底白字）和浅色（白底黑字），选择会保存，原文、Markdown、代码高亮和控制栏同步换色；设置页也可调整“预览暗黑模式”。
顶部可切换“查看原文 / Markdown 预览”，全文复制始终保留原始 Markdown；代码块支持横向滚动和“复制代码”。
轻点正文可显示或隐藏控制栏，字号调整、横竖屏和左右切换历史仍可使用。此功能渲染收到的文本，不涉及 `.md` 文件传输。
全屏控制栏直接覆盖正文，显示或隐藏时不改变正文位置。阅读期间收到新文本或图片时，会显示
“收到 N 条新内容 · 点击查看”，约 4.5 秒后收为“新内容 N”提示，直到点击查看或忽略；手动滑到新内容并停下时也会扣除对应提醒，全部看过后自动消失。不自动跳走当前阅读记录。

收到的图片可在历史卡片或全屏预览的控制栏点击“保存到相册”，原图会复制到 `Pictures/ClipRelay`，清空接收历史不会删除已保存的相册图片。Android 8–9 首次保存时需允许存储权限。
本次打开 App 期间，操作成功的内容会显示“已保存”或“已复制”，列表与全屏同步；切到后台或旋转屏幕保留状态，关闭 App 页面或结束进程后重新打开恢复默认文案。“已复制”仍可再次复制，“已保存”不重复写入相册。

### 使用 APK

1. 安装由 GitHub Actions 产出的 `ClipRelay-android-debug` APK，或按下节自行构建。
2. 手机与电脑连接同一个可信局域网，打开 App，点击“开始接收”。
3. 按系统提示允许“本地网络”和通知权限。部分厂商还需把 ClipRelay 的电池策略改为“不受限制”。
4. App 会显示 `192.168.x.x:47632` 一类地址，并在“允许局域网发现”开启时自动声明自己。在 Windows 托盘面板左侧点击“扫描添加设备”即可添加手机；扫描不到时仍可点击“+ 添加”手动填写 IP。
5. 在电脑正常按 `Ctrl+C` 可发送文本；按 `Ctrl+Alt+F12` 可发送所有显示器的截图。收到的内容会直接进入手机剪贴板。

访问密钥默认为空。若在 Android 启用，Windows 的对应广播设备也要填写相同密钥，发送请求会携带
`X-ClipRelay-Token: <密钥>`；缺失或错误的密钥会收到 `401`。

Android 0.10.11 起，可在接收设置中开启「调试时保持亮屏」（默认关闭）。接收服务运行时，只要系统的 USB 调试或 Wi-Fi 调试任一开启，就阻止自动息屏，包括未充电、切到其他 App 的情况；两项都关闭、关闭此选项或停止接收后恢复系统原有息屏规则，不修改原来的息屏时间。手动按电源键仍可锁屏。此功能依赖系统允许 App 读取调试开关，已在 Android 13 真机验证；部分较新系统可能限制读取。

### 本地构建

需要 JDK 17、Go 1.26.7、Android SDK Platform 37 和 NDK 29.0.14206865。远控客户端源码已内置于
`android-app/remote-engine/`，首次构建会同时编译原生解码/传输模块。在 Windows PowerShell 中：

```powershell
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
python scripts/build_network.py android
cd android-app
.\gradlew.bat lintDebug testDebugUnitTest assembleDebug
adb install -r .\app\build\outputs\apk\debug\app-debug.apk
```

可安装的 Debug APK 位于 `android-app/app/build/outputs/apk/debug/app-debug.apk`。正式分发时
请使用自己的 Android 签名密钥构建并签名 Release APK；不要把签名文件提交到仓库。

已有正式版的真机可使用相同签名的 QA 构建运行 Markdown 界面测试：配置本地签名后，执行
`./gradlew connectedQaAndroidTest -PcliprelayTestBuildType=qa`。测试覆盖预览/原文切换、字号、代码复制、
横向滚动与横屏，并在 App 的外部文件目录保存 `markdown-*-qa.png` 截图；测试结束后安装正式 Release 包。
手动验收文本见 [`android-app/markdown-preview-demo.md`](android-app/markdown-preview-demo.md)。

### App 自动更新

正式版会在启动时检查更新，接收服务运行期间每 24 小时再检查一次。发现新版后，App 会显示
更新说明并下载 APK；下载完成后需要按 Android 系统提示确认安装。安装包必须满足以下条件才会
交给系统安装器：

- `versionCode` 高于当前版本；
- 包名仍为 `com.cliprelay.app`；
- APK 签名与已安装版本一致；
- 文件 SHA-256 与发布清单一致。

更新源默认是腾讯云 HTTPS 服务，版本清单和 APK 都从腾讯云下载，手机无需连接 GitHub。部署说明见
[`deploy/README.md`](deploy/README.md)。推送 `android-app/`、正式发布工作流或版本脚本的改动到 `main`
后，`.github/workflows/android-release.yml` 会自动运行测试、构建签名 APK、创建
`android-v<versionName>` 标签，并发布 APK 与更新清单。无需手动修改版本号：如果当前版本不高于
已发布版本，工作流会递增补丁号和 `versionCode`，验证构建成功后将版本修改提交回 `main`；
手动指定的更高版本号会保留。没有未发布的 Android 改动时，重复运行不会产生新版本。
发布任务串行执行，并取最新 `main`；构建期间分支有新提交时不会强推覆盖，后续任务会处理最新代码。
随后 Android Cloud Sync 会同步文件到腾讯云，并校验线上版本和 APK 哈希；失败时可单独重跑同步工作流。
手工推送形如 `android-v0.6.0` 的标签或从 Actions 手动运行工作流仍可作为发布兜底。
仓库需要预先配置
`CLIPRELAY_KEYSTORE_BASE64`、`CLIPRELAY_STORE_PASSWORD`、`CLIPRELAY_KEY_ALIAS`、
`CLIPRELAY_KEY_PASSWORD` 四个 Actions Secrets；这些值必须始终对应首次正式安装使用的签名密钥。
手工标签必须等于 `android-v<versionName>`，且指向本次构建的提交，否则发布工作流会直接失败。

OPPO、realme 等带厂商后台管理的手机，还需要在 ClipRelay 的“耗电管理”中开启“允许应用自启动”
和“允许完全后台行为”。否则厂商系统可能拦截 `MY_PACKAGE_REPLACED`，导致 App 更新后要手动打开一次
才能恢复接收。标准 Android 设备不需要额外设置。

Android APK 当前支持接收电脑发送的文本和截图，尚未提供“手机 → 电脑”的发送功能。

## 配置项

Mac 配置位于 `init.lua` 顶部：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `DEFAULT_PEER` | `peer-mac.local` | 尚未扫描选择设备时使用的手动回退地址 |
| `LOCAL_PORT` | `47632` | 本机 HTTP 接收服务和 mDNS 声明端口 |
| `HOTKEY_MODS` / `HOTKEY_KEY` | `ctrl` `alt` + `g` | 全局热键，冲突可改 |

Mac 扫描选择的 `peer`、`peerPort`、`peerToken`，以及稳定的 `deviceId` 和发现开关保存在 Hammerspoon 的 `hs.settings` 中。

Windows 配置位于 `%LOCALAPPDATA%\ClipRelay\config.json`：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `peer` | 安装时的 `-Peer` | 兼容旧版本的首个启用目标地址；实际广播以 `peers` 为准 |
| `peers` | 从 `peer` 自动迁移 | 广播目标数组；手动项包含名称、地址、端口、访问密钥和启用状态，扫描项还会保存设备 ID、平台和认证状态 |
| `port` | `47632` | 本机接收服务端口 |
| `notifications` | `true` | 是否在收到文本时弹出系统气泡通知（设为 `false` 进入静默同步模式） |
| `accessToken` | 空 | 本机接收密钥；本机在非空时拒绝缺失或错误的 `X-ClipRelay-Token` |
| `deviceId` | 首次安装生成的 UUID | 用于扫描去重和排除本机，不随设备名称或 IP 改变 |
| `deviceName` | Windows 计算机名 | mDNS 中显示的发现名称 |
| `discoveryEnabled` | `true` | 是否通过 mDNS 向当前局域网声明本机 ClipRelay 服务 |

Windows 当前监听不带其他修饰键的 `Ctrl+C`。按键不会被 ClipRelay 拦截，前台应用
仍按原方式完成复制；剪贴板更新后发送新文本，等待约 300 毫秒仍未更新时发送剪贴板当前文本。
剪贴板为空或只有图片、文件等非文本内容时不发送。可以先点击网页的“复制”按钮，再在没有选中文本的位置按 `Ctrl+C` 发送；
若当前应用把 `Ctrl+C` 解释为复制整行等操作，则发送该操作产生的新文本。左键点击
托盘图标可打开设备链路控制台，配置广播设备、本机端口、本机接收密钥、开机自启和接收气泡通知（静默模式）；也可右键托盘图标快速切换通知状态或选择 `退出 ClipRelay`。
同一段文本在 1 秒内连续按普通 `Ctrl+C` 只发送一次；不同文本仍会立即逐条发送，发送失败也不会阻止下一次重试。
广播设备列表变化后，防抖签名也会随之变化；新增目标不会被上一条单设备发送记录误抑制。

截图快捷键固定为 `Ctrl+Alt+F12`。它会被注册为全局热键，不再传给前台应用。
ClipRelay 启动时会检测系统级热键冲突：
注册成功时托盘菜单显示“可用”；如果已被其他程序占用，托盘菜单显示冲突并弹出一次警告，
截图功能保持停用，但 `Ctrl+C` 文本同步和接收服务会继续运行。截图覆盖
整个 Windows 虚拟桌面（所有显示器），以质量 88 的 JPEG 在内存中只编码一次，再通过并行的 `/push-image`
请求广播；发送端不调用系统截图 UI、不写临时文件、不修改本机剪贴板，成功或失败也不会弹通知。
接收端会拒绝超过 25 MiB、格式错误或像素尺寸异常的图片。

## 远程桌面与屏幕共享

Windows 主界面和托盘统一从「远程桌面」进入：

- 「控制其他电脑」：连接已配对电脑，查看画面并操作键盘鼠标。
- 「允许设备连接」：开启本机远控，管理手机和电脑的配对及授权。
- 「共享本机屏幕 · 仅观看」：邀请局域网内的 Windows 电脑观看主屏幕，对方不能操作键鼠；可在此页、主界面的共享状态栏或托盘结束共享。

远控本身包含画面观看。仅观看共享保留由本机发起、对方接受的邀请流程，归入同一入口；打开入口不会自动开启远控或开始共享。

### 手机远程操作电脑

Windows 安装包内置远控引擎；Android APK 内置客户端。双方只需安装 ClipRelay，
不用单独安装 Sunshine、Moonlight 或 Tailscale，也不需要注册 Tailscale 账号。
内置外网连接优先尝试设备直连，无法直连时使用 ClipRelay 服务器中转；手机可以使用移动网络。

1. 电脑运行 ClipRelay 安装程序，允许安装 `ClipRelay Remote Desktop` 后台服务。
2. 打开电脑 ClipRelay 的「远程桌面 → 允许设备连接」，点击「开启远控」。首次安装默认关闭。
3. 手机和电脑连接同一局域网，手机首页点击「连接电脑」，电脑会自动出现在列表中，点选即可发起配对。
4. 核对手机和电脑显示的确认标识，在电脑「允许设备连接」中允许一次即可，不需要手填 IP 或 PIN。旧版电脑继续使用四位 PIN。
5. Android 0.10.17 起，点击「连接这台电脑」后直接进入画面，首次配对完成也会自动连接；已有串流时自动恢复，无需再打开连接选项或点击恢复串流。电脑有其他游戏串流时会恢复该串流，不会将其关闭。Android 0.10.13 起，横屏时如果桌面画面两侧留有足够宽的黑边，操作按钮会自动常驻在左右黑边中，无需收起或展开；按钮较多时可在侧栏内上下滑动，中央桌面画面保持原来的大小。侧栏避开屏幕缺口、系统栏与手机键盘。没有足够黑边时，仍可点右侧边缘的半透明「⋯」展开底部工具栏，小圆点可上下拖动并记住位置。
   工具栏中的「触控」可选择手机触控、直接点击或触控板，选择会保存到下次连接，也可在「画质与操控 → 触控方式」中修改。
   Android 0.10.19 起，展开工具栏点「返回电脑列表」（游戏模式在右上角菜单中），或使用系统返回，直接回到带「重新扫描」「其他添加方式」的电脑列表，不再弹出画中画小窗。返回时停止手机端画面接收并释放键鼠控制，电脑上的应用和会话保留；再次点击这台电脑即可恢复控制。键盘打开时，系统返回仍先收起键盘。

Android 0.10.12 / Windows 0.3.4 起，局域网发现同时使用 ClipRelay mDNS 和 UDP `47634` 查询，后者绑定 Wi-Fi / 有线网卡以兼容手机开启 VPN 的情况；只返回设备名和服务端口，不广播凭据。首次授权通过独立的 TLS `48792` 通道，两端确认标识绑定电脑证书、手机证书和随机数，电脑通过本机受保护的控制接口允许后才提交远控配对。等待两分钟自动过期，手机可以取消。配对证书立即保存，重启保留；重新发现按远控 UUID 合并地址并核对保存的证书，IP 变化不会新增重复电脑或重置配对。手动 IP 和外网配对码在「其他添加方式」中。

新版 Windows 配对界面需要勾选「两端确认标识一致」后才能允许请求，也可直接拒绝。操作绑定本次请求，已取消或被替换的旧请求不能继续批准；桌面和 Android 新连接端可收到拒绝反馈。新服务通过受保护的本机管道处理这些决定，停止使用旧版批准文件。[完整包与临时 Windows 安装验收](https://github.com/ffffhx/cliprelay/actions/runs/38882004035)已验证实际 SYSTEM 服务、原生证书握手、拒绝反馈及未授权证书拦截；下载包的 742 个文件和源码版本核验一致。记录见 `.tools/uu-parity/windows-host-pairing-artifacts.json`。

Windows 撤销授权会先停用设备并确认，再删除配对并确认；响应丢失后只读取实际状态，不自动重复修改或恢复授权。操作绑定当前引擎和设备身份，重启前的旧列表及重新配对前的旧身份不能继续用于撤销；部分完成时显示「已停用」并要求刷新。[两台设备的实际安装验收](https://github.com/ffffhx/cliprelay/actions/runs/38884453648)通过 10 项场景：被撤销设备的新连接和已建立的控制 TLS 连接均被拒绝，另一台仍可访问，重启后撤销保留。下载包的 743 个文件、148 个引擎文件和源码版本核验一致，记录见 `.tools/uu-parity/windows-host-revocation-artifacts.json`。该记录验证证书和控制连接；实际视频验收见下文。

实际视频撤销已通过[临时 Windows 安装验收](https://github.com/ffffhx/cliprelay/actions/runs/38893871348)：第一台设备收到加密 H.264 视频后，从 SYSTEM 服务撤销其授权，客户端在 1192 毫秒内正常结束，随后另一台仍获授权的设备在同一引擎进程收到新的视频串流。旧证书发起的远控请求返回未授权。验收使用固定版本的完整安装包，记录原生结束码 0，且未通过本地停止接收器或重启引擎来代替撤销。测试在 CI 虚拟显示器上进行，只统计压缩视频帧，不解码展示或保存画面；手机界面、实际硬件、两路同时串流及 Mac 视频仍需单独验证。记录见 `.tools/uu-parity/native-active-revocation-artifacts.json`。

Windows 服务对本机引擎的管理请求核对完整证书，限定操作和响应大小，拒绝代理及重定向，并对整个请求设置截止时间。即使引擎不断缓慢发送数据，也不能无限延长等待；修改请求丢失响应后不会自动重发。8 项实际 C# HTTPS 测试覆盖这些异常，[新版完整包](https://github.com/ffffhx/cliprelay/actions/runs/38885442103)重新通过 10 项安装版配对与撤销场景，[三平台回归](https://github.com/ffffhx/cliprelay/actions/runs/38886130534)通过。记录见 `.tools/uu-parity/windows-engine-admin-artifacts.json`；多次请求合计的撤销时限仍需单独做故障注入验收。

需要从外网连接时：电脑「远程桌面 → 允许设备连接 → 外网配对」开启内置通道并生成八位配对码；
手机「连接电脑 → 其他添加方式 → 用配对码添加」输入该码。核对两边显示的六位标识，在电脑允许这台手机，
待手机显示就绪后点击「连接电脑」。如果此前已在局域网完成配对，外网连接会沿用授权；仅通过外网首次配对时，仍需在电脑端输入手机显示的四位 PIN。
配对码五分钟有效、只能使用一次。之后打开电脑列表即自动恢复已启用的通道，并按电脑身份合并局域网和安全通道地址，不需要选择内外网模式。

Android 0.10.8 起，内置通道会自动重建异常退出的 UDP 转发端口，避免电脑仍显示在线但实时控制无法握手；恢复期间显示「正在恢复串流通道」。内置通道连接失败时提供重试提示，不再显示原引擎不适用的公网 47999 端口建议。
Android 0.10.6 起并行探测保存的地址，优先选局域网；内置通道已响应时，最多额外等待 400 毫秒争取更优先的路径，避免失效的旧地址拖住连接。每条路径仍核对电脑身份并使用已保存的配对证书。此选择发生在连接前；串流中换网可能仍需重新连接。
手机「暂停安全通道」会保留配对且仍可局域网直连；电脑可分别关闭外网连接、撤销外网配对或撤销远控授权。
手机可保存多台电脑的外网配对，各自建立独立的安全通道；在电脑列表中选择目标即可连接，无需重新输入配对码。升级会保留旧配对及原地址，添加新电脑失败或取消时不影响已有电脑。每台电脑仍最多允许八台手机。
在「连接电脑 → 其他添加方式 → 用配对码添加」进入外网电脑管理页，可继续添加其他电脑，并逐台暂停、恢复或移除。移除只删除这台手机保存的对应外网配对；其他电脑和局域网发现不受影响，电脑端仍可撤销远控授权。通知栏的「全部暂停」保留全部配对，之后可逐台恢复。每台电脑的设备凭据、网络状态目录及本地转发地址相互独立。
此版本内置外网通道用于手机远控；剪贴板同步和电脑之间的屏幕共享仍使用原有设备地址与访问密钥。

设备密钥保存在各端私有目录中，Android 的设备凭据由系统 Keystore 加密并排除备份。
配对与协调服务部署在现有腾讯云更新服务器上，设备之间使用 WireGuard 加密。
不同电脑的配对组由服务端访问规则隔离，电脑还会检查手机地址白名单；公网不开放远控管理接口。
中转会消耗服务器带宽，适合个人使用的容量需按实际串流码率规划；直连画面不经过服务器。

「手机触控」将手指操作作为真实触屏输入传给电脑：点按、单指滑动滚动、双指捏合缩放和长按菜单由电脑软件处理。
Android 0.10.28 起，手机和平板统一默认 1920×1080、60 FPS，默认使用「手机触控」。升级时原有 1280×720 / 1280×960 设置一次性调整为 1080P，其他分辨率及帧率保持原选择；之后手动选择较低分辨率仍会保存。已经明确选择的触控模式仍会保留。返回电脑列表后，右上角齿轮进入「画质与操控」，可更改分辨率和触控模式。两端共用同一套工具栏：两侧空白足够时显示侧栏，否则使用底部菜单；按钮按应用模式展示，已移除聊天工具栏中的「换行 ⇧Enter」。
手机触控默认发送原生触屏手势，使用 Windows 的圆形触点反馈。Android 0.10.31 起，识别到 Orca 前台应用时，单指保持原生触控，双指张开／捏合转换为 Ctrl+=／Ctrl+- 调整当前终端字号，双指平移转换为滚轮。先点选目标终端；需要保留 Orca 默认缩放快捷键。手势经过防抖后锁定为缩放或滚动，抬起任一手指、加入第三指、切换应用或失去焦点即结束，不会把剩余手指变成点击，也不会持续按住 Ctrl。直接点击和触控板模式仍使用双指滚动。
Android 0.10.26 起，识别到 ChatGPT / Codex 前台应用时，单指滑动自动转成鼠标滚轮，兼容其禁止触屏滚动的会话侧边栏；滚动固定作用于手指起点，轻点左键、长按右键，滑动结束不会点击会话。双指在开始滚动前落下时仍发送原生捏合手势；已开始单指滚动后加入第二指会取消本次手势。其他应用保留原生触控。手势兼容根据电脑实际前台应用自动生效，不需要选择专用工具栏；旧电脑端没有应用识别时，可以通过「更多 → 触控方式」使用直接点击或触控板的双指滚动。需要拖拽会话排序或选字时可使用直接点击模式。
滚动、缩放和选字效果取决于软件的触屏支持，电脑界面不会变成手机版。「手机触控」点进可编辑输入框后会自动弹出手机键盘，点到普通按钮或只读区域后收起自动打开的键盘；手动收起后不会反复弹出。
自动键盘需要新版 Windows 端和 Android 端。自绘控件、部分游戏或旧版电脑端可能无法提供输入焦点，此时仍可从工具栏打开「手机键盘」。
Android 0.10.27 起，ChatGPT / Codex 的兼容触控在手机画面上显示跟手圆点，抬手后淡出；切换模式、切换应用或取消手势会立即清除。圆点由手机本地绘制，不接收点击，不会影响滚动落点，也不改变 Windows 的系统光标；原生触控和双指手势继续使用电脑端原有反馈。
Android 0.10.22 起，输入法反复修订语音识别或拼音候选时，临时文字和组合范围保留在手机端，确认文字后才转发到电脑，避免将每次识别的半句话重复追加。正常连续输入相同词句仍会逐次发送。
手机键盘同步光标和候选范围，并在批量编辑结束后更新输入法状态，修复豆包输入法英文联想逐字重复追加的问题；候选退格和连续输入相同单词仍正常保留。
如果手机连接了实体键盘，或 scrcpy 使用了键盘模拟，Android 可能禁止显示手机键盘。请在手机系统「实体键盘」设置中开启「使用屏幕键盘」。Android 0.10.5 同时修复了前台应用识别更新时取消刚刚点击后的键盘检测的问题；手动收起、切后台与断开连接仍会取消检测。
电脑通过 Windows UI Automation 核对轻点位置是否命中当前可编辑输入框，不读取文字、控件名称或密码。切换会话后自动获得焦点、点击空白处仍保留输入焦点，都不会自动弹出手机键盘；重新点击输入框才会唤起。此判断需要新版电脑端和手机端，旧版电脑端保留手动键盘入口。焦点通道使用现有远控配对证书进行双向 TLS 验证，撤销配对后立即停止访问。
拖动窗口、精确选字或操作老软件时可以切回「直接点击」「触控板」。不支持触屏输入的电脑会提示并切换为直接点击。
手机和平板查看电脑时，三指左右滑切换虚拟桌面，四指左右滑切换显示器：左滑到下一个，右滑到上一个，全部抬手后执行一次。显示器按「更多 → 显示器」中的列表顺序循环，等新画面显示后恢复输入；只有一块显示器时会提示。桌面切换通过已配对电脑的只读状态识别 Windows / macOS，分别发送系统默认的 Win+Ctrl+方向键 / Ctrl+方向键；需要电脑已创建多个桌面，旧主机无法识别系统时提示更新，不猜测快捷键。两个手势适用于手机触控、直接点击和触控板，游戏模式不启用。第三指落下时会取消已有触点，短滑、纵向滑动、取消或失焦不切换；直接点击和触控板仍保留三指轻点唤出键盘，手机触控不使用三指轻点。安卓系统的三指截屏可能拦截手势，可在设备设置中关闭该快捷手势。操作说明位于「更多 → 触控方式 → 操作说明」。

操作模式只保留「通用桌面」与「游戏模式」，通过「模式」按钮手动选择；默认进入通用桌面，旧的 ChatGPT / Orca 工具栏选择不再生效。切换电脑前台应用不会改变操作模式或游戏按键布局。后台应用识别仅用于触摸兼容和切换应用时释放输入，只传输预设应用标识，不读取或传输窗口标题、应用路径及内容，沿用远控配对加密通道。
通用桌面左侧依次为模式、手机键盘、虚拟键盘、语音输入、传图片；右侧依次为返回电脑列表、Enter、退格图标、Esc、Win、更多。复制、粘贴、全选、触控方式、撤销、重做、上下滚动、串流信息和断开连接统一放在「更多」中。画面两侧空间不足时，底部工具栏提供相同按钮。底部黑边能容纳整条工具栏时（例如平板显示 16:9 桌面），工具栏常驻展开并隐藏「收起」，不覆盖或缩小电脑画面；系统栏或键盘占用空间后重新判断。模式切换释放旧按键和触点，不会启动应用或向应用发送文字。

开发版侧栏、底部工具栏与「更多」中增加「自定义键」。可保存最多 12 个具名快捷键，选择 Ctrl / Alt / Shift / Win 与字母、数字、F1–F24、导航键等组合，并支持编辑、删除、上移和下移。配置保存在本机，供各台远程电脑共用；点按时先按修饰键，松开时先释放普通键，结束后不保持任何按键。游戏布局和 Orca / ChatGPT 控件继续独立使用。
「复制」操作的是电脑剪贴板。「更多」中的「粘贴：电脑」粘贴电脑当前剪贴板；「粘贴：手机」（平板显示「粘贴：平板」）读取点击时的本机剪贴板，先传送文字、链接或图片，电脑确认写入成功后自动粘贴。传输失败、取消或断线时不会继续粘贴电脑里的旧内容。滚动作用于电脑鼠标所在区域。

「虚拟键盘」以小型悬浮面板显示，拖动顶部「⠿ 拖动」即可移动，松手记住位置。横屏手机宽度约为可用画面的 65%，平板约为 50%；高度随屏幕调整，并保留最小按键高度。旋转、分屏或系统栏变化后面板保持在可见区域内，面板外仍可操作电脑画面。
面板提供字母、数字、Ctrl、Alt、Shift、Win、Tab、Enter、退格、空格与方向键；「功能」页包含 F1–F12、Esc、Delete、Insert、Home、End、Page Up/Down 和标点。先点亮修饰键，再点其他键发送组合（例如 Ctrl → C、Ctrl → Shift → Esc），也可点亮 Ctrl 后点击电脑画面中的链接。完成后自动松开，再点同一个修饰键可取消选择，长按修饰键则单独发送该键。
点击「×」或手机返回键关闭面板；「输入法」切换到系统输入法，适合输入中文。游戏模式可从右上角「⋯ → 虚拟键盘」打开，关闭后恢复游戏按键。失焦、断开、切换应用、旋转和关闭面板会清除未发送的组合键，键盘区域及拖动手势不会把触摸传给电脑画面。

Android 0.10.23 / Windows 0.3.5 新增侧边栏「语音输入」：先选中电脑输入框，点击按钮并允许手机麦克风权限，看到「请对着手机说话」后开始说话，点击「结束说话」由电脑豆包输入文字；不会自动按回车发送。使用的是手机麦克风，无需打开手机键盘，远离电脑也可使用。
电脑需要正在运行的豆包输入法，以及已启用的 Steam Streaming Microphone 或 VB-CABLE 虚拟声卡。ClipRelay 临时选择虚拟麦克风，结束后恢复原选择；不修改系统默认麦克风或音频格式。音频沿用现有远控配对的双向 TLS 通道，以 16 kHz 单声道 PCM 在内存中转发；识别由豆包处理，遵循豆包自身的联网与隐私设置。
每次最长约 3 分钟。切后台、断开、切换电脑窗口或 6 秒未收到声音数据时取消录音。豆包可能在说话过程中实时输入文字；取消会停止后续录音和输入，已经输入的文字仍保留。当前适配 Windows 豆包 0.9.1.22、0.9.2.7 的本地接口；它会忽略模拟快捷键，因此无需修改快捷键。该接口不是公开 SDK，豆包升级到尚未验证的版本时会明确提示需要电脑端适配，不继续发送不兼容的命令。
开发验证：`windows/tests/voice-input.ps1` 检查版本兼容限制；`-Live` 在专用测试输入框中用合成中文语音验证豆包转写与麦克风恢复，不录制真实麦克风。手机权限、生命周期与实际网络仍需真机验收。

开发版新增两种独立的手机语音方式：长按「语音输入」，或从「更多 → 语音输入方式」选择。本机识别使用 Android 12 及以上的 [公开本机识别接口](https://developer.android.com/reference/android/speech/SpeechRecognizer#createOnDeviceSpeechRecognizer(android.content.Context))，需要手机提供可用服务和对应语言模型；系统语音服务使用 Android 的公开识别接口，可能由其提供方联网处理。模式不会在失败时自动切换；原有电脑豆包入口与默认设置保留。手机识别最长 60 秒，最终结果先显示在手机上，可编辑后点「输入到电脑」，仅输入一段文字，不按回车。识别中的半句、重复或过期回调不会输入；后台、画中画、断线、显示切换或切换应用时取消。输入结果不保存为文件，失败后不自动重发。

输入能力验证：Android 256 项本地测试通过，包含 12 项语音状态与自定义键测试；4 项新增界面测试已编译，尚未运行。普通串流文本发送已改为标准 UTF-8 字节，避免 JNI Modified UTF-8 对非 BMP 字符的影响；语音确认路径同时检查底层队列返回值。`python android-app/tools/test_text_jni.py --java-home D:/jdk17` 使用原样生产 Java / JNI 方法与独立记录队列，验证中文、非 BMP 字符、零字符、长文本、返回码、空输入和原有调用入口，共 7 项通过。四种 Android ABI 构建和符号检查、QA、lint、签名通过；这些结果不代表真实手机语音、Android JNI 加载或远端显示已经验收。

先点选电脑上 Orca、ChatGPT 或其他支持图片粘贴的软件输入区，再点远控工具栏的「传图片」，会直接打开手机系统相册选择器。选好后通过现有配对加密通道上传，自动返回串流并执行一次 Ctrl+V，无需再次确认上传或手动粘贴，也不会自动按回车发送消息。取消选图会直接返回；上传失败可重试，不会触发粘贴。选择器仅授权选中的图片，不需要读取整个相册。支持手机可解码的常见图片，源文件上限 20 MB；大图适度缩小后转为 PNG，保留透明通道并去除源元数据，传输上限 8 MB。自动上传及粘贴需要 Windows 0.3.3、Android 0.10.10 或更高版本；选图期间暂停串流，电脑应用继续运行。

当前开发分支新增「更多 → 显示器」：通过配对通道列出、刷新和选择电脑上可采集的显示器，保留视频连接；切换时释放按住的按键和触控，等目标画面实际显示后恢复输入。自动键盘检测按当前显示器的物理坐标和画面黑边映射，拒绝过期串流或引擎重启前的请求。多台设备观看同一电脑时，切换会影响所有观看设备。需要配套的修改版串流引擎；现有安装尚未更新，实际多屏、热插拔与手机界面仍待验收。可识别已经安装且能采集的虚拟显示器，暂未提供虚拟显示驱动安装。源码补丁、构建与接口说明见 [engine/sunshine](engine/sunshine/README.md)。

当前开发分支新增「更多 → 隐私与锁屏」：手机前台远控时可遮住 Windows 电脑的显示器，本机按 `Ctrl + Alt + Shift + P` 恢复。仅允许当前唯一的已配对串流开启；退出、切后台、超时、配对撤销、显示器变化或引擎状态无法确认时恢复显示，恢复后需要用户再次开启。需要 Windows 10 2004 及以上、DWM 合成和配套修改版引擎。此功能是可由本机退出的桌面遮罩，不覆盖锁屏、UAC 等安全桌面，也不锁定本机键鼠。

当前开发分支新增电脑列表长按菜单「远程唤醒设置」。目标电脑在线且已配对时，读取 Windows 物理网卡、魔术包唤醒和电源设置；选择已连接的网卡，再选择目标局域网中另一台已配对、在线且运行新版 ClipRelay 的电脑作为助手。设置绑定两台电脑的配对证书，保存 30 天；目标离线后，从原「唤醒」菜单发送请求。手机可通过现有跨网通道联系助手，由助手向自己的局域网代发唤醒包。选择助手时需确认它确实在目标局域网；相同网段地址不代表一定属于同一个物理网络。没有助手时仍可明确选择「从当前手机发送」，通常需要手机在目标局域网。

`POST /v1/wake` 复用配对双向 TLS。助手只向当前已连接物理网卡的指定匹配网段广播固定的 102 字节魔术包，端口固定为 UDP 9，每个出口发三次；不接受任意目的地址、端口或命令。配对证书隔离请求回执，两分钟内相同请求不重复发送；每个客户端十秒最多一轮，全局每分钟最多六十轮。手机收到发送回执后最多等待一分钟，并通过目标电脑的固定证书再次读取状态，才显示「电脑已上线」。丢失回执、等待超时和硬件能力不明都有独立提示；退出页面会取消请求和等待，不后台自动重试。

网卡检测只读，不自动改 BIOS、电源设置、快速启动或网卡属性。配置已启用也不等于硬件唤醒已实测；[Windows 网卡电源管理定义](https://learn.microsoft.com/en-us/windows/win32/fwp/wmi/netadaptercimprov/msft-netadapterpowermanagementsettingdata)规定电源管理未启用时，其余设置可能没有定义，因此此类状态显示「待确认」。`windows/tests/wake.ps1` 验证检测逻辑；Go `TestWake*` 覆盖授权、局域网出口、重试、撤销和真实双向 TLS，UDP 内容测试只发往本机回环。Android `WakeStateTest` 覆盖协议、配置过期、证书绑定、取消及真实 Windows 检测输出；配置 `CLIPRELAY_WAKE_TEST_WORKER` 指向测试程序或完整服务程序即可运行跨进程检查。完整服务和 Android QA 包已构建，实际睡眠/关机唤醒、安装版 SYSTEM 服务和 Android 界面操作仍待验收。

`POST /v1/privacy` 使用双向 TLS，将操作绑定到配对证书、引擎实例、串流和随机租约；桌面用户 worker 独立计时，15 秒未续约即撤罩。遮罩使用 [WDA_EXCLUDEFROMCAPTURE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)，不改变显示器电源、分辨率或音频。已通过生命周期、授权和恢复测试，以及生产遮罩在小型自有测试窗口上的真实 DXGI 捕获验证；正常退出与强制结束进程均移除遮罩。验证入口为 `windows/tests/privacy-screen.ps1`、`privacy_capture.py` 和 Go `TestPrivacy*`；捕获测试先用 LLVM-MinGW 编译 `privacy-capture.cpp`（`-D_WIN32_WINNT=0x0A00 -DWINVER=0x0A00 -ld3d11 -ldxgi -luser32 -lole32`），只读测试窗口内的一个像素。完整 Sunshine 编码串流、实际全屏/多屏与 Android 界面、SYSTEM 用户进程切换仍待验收；已安装服务未替换。被控端静音的实现和验收进度见下文。

同一菜单可独立开启「本次远程结束后锁屏」，默认关闭，仅绑定当前唯一的配对串流。`POST /v1/session-lock` 只接受 `status`、`arm` 和 `disarm`；手机不能直接提交锁屏，也不负责维持锁屏计时。电脑端每秒检查引擎，在持续空闲至少 1.5 秒后再次确认没有任何串流，再由桌面用户 worker 先移除隐私遮罩、后发起锁屏。短暂控制故障不表示会话结束；出现新串流、引擎重启、配对撤销、本机会话变化或持续无法确认状态会取消安排。切后台只恢复遮罩，已开启的结束锁屏安排继续由电脑端跟踪；服务或 worker 退出时不额外锁屏。

锁屏是一次性操作，回执丢失或用户解锁后都不重试。[LockWorkStation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-lockworkstation) 返回成功仅表示已发起，实际成功需收到本会话的 `WTS_SESSION_LOCK` 通知；没有通知会报告未确认。`windows/tests/session-lock.ps1` 用模拟工作站验证策略，Go `TestSessionLock*` 覆盖授权、撤销、引擎状态、断开判断和真实 worker 通信；测试没有实际锁定用户电脑。Windows 工作站锁定/解锁、完整 Sunshine 断开流程、Android 菜单及后台行为仍待实机验收。

被控端静音已接入桌面用户工作进程、配对控制接口 `/v1/audio-mute` 和手机“隐私与锁屏”菜单。菜单分别提供隐私屏、电脑扬声器静音、结束后锁屏，并显示当前状态；手机退出远程画面、后台或画中画时会请求恢复声音。接口只允许唯一的当前串流持有静音，并绑定音频采集代次；端点采集、音频未就绪或采集重建时拒绝开启或续期。断线、撤销配对、过期、工作进程失效、设备变化和本地手动调整会触发恢复；丢失响应后仍重试恢复，已取消的请求在两分钟重试窗口内不能重新开启。恢复记录存于桌面用户的 `%LOCALAPPDATA%\ClipRelay\audio-mute.json`，服务每分钟检查新出现的崩溃记录，未完成的恢复每 30 秒重试；工作进程自己还维持独立的 15 秒到期恢复。`windows/tests/audio-mute.ps1` 的 26 项场景、Go 的 11 组静音控制测试及 Android 的 221 项单元测试通过，QA 构建和检查通过。静音不修改音量或默认设备，并保留 Steam Streaming Microphone / VB-Audio 的语音输入通道。

修改版引擎的完整构建和加密串流音频测试已通过：已有、非默认的 Steam 虚拟扬声器上生成的测试音，经采集、Opus 编码、传输和解码后，静音前、静音中、恢复后的幅度均为 0.005031733，串流和音频采集代次不变，设备设置恢复一致。服务通过受信配置 `cliprelay_audio_exclude_pid` 指定自身 PID；引擎验证存活的父子关系和创建时间，排除服务及语音输入工作进程，避免回音。完整串流反例中，旧引擎会传回模拟语音输入的测试音，新引擎接收端测得为 0；普通应用的测试音仍正常传输。无声程序的独立采集也保持健康。复现入口为 `windows/tests/engine_control_test.py <engine目录> --stream-client <测试接收器> --audio-test <audio-loopback.exe> --audio-host-root`。测试未改变真实扬声器或保存原始音频。新采集使用 [Windows 按进程采集接口](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/)（系统构建 20348 及以上），开发选项 `cliprelay_process_audio` 仍默认关闭，当前仅支持 48 kHz 双声道；其他情况保留原采集且不报告静音支持。真实声卡、SYSTEM 恢复、Android 实际操作和安装版整链路仍待验收，当前结果不代表这些项目已完成。

当前开发分支新增「更多 → 剪贴板同步」：在已配对电脑的远控中，主动发送手机剪贴板或取回电脑剪贴板，支持纯文本和图片；收到后手动粘贴，不自动向电脑应用发送按键，也不后台监听剪贴板。该入口使用双向 TLS 和保存的电脑证书，旧电脑端不支持时提示更新，不退回 HTTP。文字上限 1 MiB（UTF-8），图片转为 PNG 后上限 8 MiB、600 万像素；电脑桌面锁定时拒绝读取和写入。

接口为 `POST /v1/clipboard`，支持主动 `read` / `write`，以及用于桌面自动同步的 `observe` 和带 `expect` 版本条件的 `write`；写入的随机请求 ID 按配对证书隔离，进程内保存最近 256 次写入摘要，近期重复请求只确认而不再次覆盖剪贴板。每次请求以及读取结果返回前检查配对撤销。Windows 的剪贴板 worker 使用登录用户令牌和 STA 线程，stdin 关闭后退出，不保存剪贴板历史。`windows/tests/clipboard-exchange.ps1` 使用模拟剪贴板测试；将生成的 worker 路径传入 `CLIPRELAY_CLIPBOARD_TEST_WORKER` 后，Go 测试还会验证真实 C# 跨进程往返。手机实际 UI、SYSTEM 到用户进程和服务部署仍待验收。

开发分支也新增普通 Windows `Ctrl+C` / 截图的配对广播：先完成手机远控配对，在 Windows「添加接收设备」中选择已配对的手机，并在手机开启接收。该目标固定绑定配对证书，不依赖局域网 IP；通过现有双向 TLS 通道传输，失败不会转为 HTTP。发送状态需等手机处理完成并返回回执。文本 JSON 上限 1 MiB，JPEG 上限 25 MiB；屏幕预览翻页控制暂不支持此新目标。

手机主动长轮询 `POST /v1/relay`，不新增手机监听端口。Windows 常驻服务使用受保护的本地管道向内存队列发布，发送前校验管道所属进程；队列总容量 64 MiB，每台手机最多 16 条未完成消息，内容最迟五分钟清理。手机保存消息 ID、摘要及处理状态，回执丢失后不重复覆盖剪贴板；处理中崩溃或无法持久化结果会拒绝该条消息，需要用户重新发送。接收记录最多 4096 条，保留一小时。新增 `windows/tests/paired-relay.ps1`、`paired-targets.ps1` 和 Android `RelayDeliveryTest`；设置 `CLIPRELAY_RELAY_TEST_WORKER` 可运行 Go 到真实 C# 发送器的协议测试。此链路已做本地协议与构建验证，Electron 实际界面、Android 前台服务和安装后的 SYSTEM 服务仍待验收。Windows、Android 和 Mac 的旧版 HTTP 收发现已改为明确开启的兼容模式，升级时保留地址和密钥，但不会自动允许明文传输。Mac 加密配对客户端已接入相同的证书握手和广播回执协议，支持选择一台电脑收发；Mac App 打包、系统钥匙串与实际界面仍未在 macOS 验证。

当前开发分支新增「文件传输」：在电脑列表长按已配对的在线电脑，或在远控「更多」菜单中进入。可浏览电脑用户目录、桌面、文档和下载目录；上传时支持系统文件选择器多选，下载时先勾选多个文件，再选择手机保存目录。队列显示进度，支持暂停、继续和取消；应用进程退出后保留记录，重新打开后由用户点击继续。进入文件页面会暂时停止视频串流，返回后重新连接；文件队列通过独立前台服务运行。

文件通道复用远控的双向 TLS 身份，电脑在每次请求检查配对撤销，文件读写使用登录用户权限。分块和完整文件均校验 SHA-256；同名文件自动改名，不执行收到的文件。Windows 暂不支持链接、联接点和带重解析属性的云盘路径；Android 下载先存入应用私有临时文件，校验后发布到所选目录，因此手机需要临时文件及最终文件的空间，保存目录需支持重命名。后台服务超过系统时限会保存进度并暂停。此功能尚未发布，Android 设备和实际 Windows 服务验收仍待完成。

独立终端已接入 Windows 和 Mac 被控端，Android 与桌面客户端按电脑返回的能力选择 Shell，设备界面及生产安装验收仍待完成。Windows 后端接入 [ConPTY](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session)，通过配对双向 TLS 的 `POST /v1/terminal` 管理交互式 cmd / Windows PowerShell 5.1。Shell 使用登录用户的非管理员令牌，拒绝继承 SYSTEM 或提升后的令牌；不自动加载 PowerShell 配置文件或 cmd AutoRun。每台配对设备最多四个运行中的会话，电脑总计最多八个，重新连接可列出原会话并按字节位置继续读取 UTF-8/VT 输出。每个会话保留最近 1 MiB 输出，超出时明确报告缺口；连续 30 分钟没有访问会结束会话。

创建会话和写入使用独立递增序号，丢失回执后的同序号重试不会再次创建 Shell 或输入命令；工作进程重启后，旧实例请求被拒绝。输入队列与输出均有容量限制，接口区分「输入已接收」和「已写入终端」，不把它们当成命令执行成功。服务每三秒同步配对授权；撤销配对会结束对应会话，工作进程二十秒收不到有效授权也会自行结束会话。关闭、退出及撤销使用独立进程 Job 清理 Shell 和子进程，输出处理与 ConPTY 关闭分线程进行，避免旧版 Windows 关闭时死锁。

Mac 使用普通登录用户的原生 PTY，支持交互式登录 zsh / bash，读取用户的 Shell 配置并保留前台程序的正常终端模式。它复用配对授权、多会话、输出续读、重复请求保护及鼠标协议；拖拽停止续期后由主机释放，尺寸或鼠标模式变化会使旧手势失效。每个会话由独立守护进程监测父进程；主服务退出、被强制结束或授权撤销时，关闭所属 Shell。主动脱离会话的守护任务不属于已验证的进程清理范围。长粘贴保留 3 秒无写入进展超时和 30 秒总时限；超过安全长度的单行输入需等待行编辑器，避免被系统规范输入缓冲截断。

Android 0.10.20 起，「画质与操控 → 自动调节码率」默认全自动：隐藏手动码率滑块，忽略旧的手动上限，按所选分辨率和帧率生成起始预算与内部质量范围。系统允许在起始预算的两倍以内探升（最高 150 Mbps），这只是内部保护范围，不代表实测带宽。客户端根据持续丢帧或有视频负载时相对基线持续增长的延迟降低预算；只有视频实际使用了足够预算、延迟正常且稳定约 3 分钟，才小幅提高预算，用真实视频试探带宽。静止桌面、短暂大帧、过期统计或无数据不会触发提速；探升需在真实负载下验证，失败后回退并退避至少 10 分钟。默认可降到 1 Mbps（更低的起始预算保持更低），两次降低至少相隔 30 秒。关闭自动调节才显示原来的手动码率，保存值不会被自动调整覆盖。当前内置引擎只在建立连接时协商码率，因此调整会短暂重连；分辨率、帧率、电脑应用、游戏模式、触控方式及工具栏状态保留。退出或连接失败时不会循环自动重试。

「移动网络自动省流」也默认开启：根据 Android 当前默认网络识别移动数据或计费网络（包括被系统标为计费的热点），采用最高 6 Mbps 的省流预算；普通 Wi-Fi / 非计费网络恢复按分辨率和帧率生成的正常预算。手动模式下低于 6 Mbps 的设置仍有效，不修改保存的分辨率、帧率或码率偏好。省流限制独立于拥堵调节开关，自动探升也不会突破省流预算；两项均关闭时按手动码率串流。启动时暂时无法识别网络则先采用省流预算，切网期间未知状态不会解除已有的限制。VPN 按系统报告的底层传输类型及计费属性判断，内置外网通道本身不代表正在使用移动数据。自动模式下即使关闭省流也会监测网络类型变化、丢弃旧路径上的拥堵判断。切网后会重新探测已配对电脑的可用地址，并短暂重连；小窗串流同样受省流限制。

## Windows 之间实时屏幕共享

两台 Windows 电脑更新后，在发送方控制中心顶部点击「屏幕共享」，或在托盘菜单选择「屏幕共享 · 实时视频」，
选择接收电脑并点击「开始共享」，直接共享 Windows 主显示器的完整画面，无需再选择屏幕或窗口。
接收方点击「接受并观看」后播放实时画面，支持全屏。多显示器时共享主显示器，不拼接所有显示器。
屏幕共享可以单独选择已添加的 Windows 电脑，不要求开启该设备的剪贴板广播开关。
发送方在后台共享，不弹出状态窗口、不占用任务栏；右键 ClipRelay 托盘图标可查看等待接收、正在共享等状态，并选择「停止所有屏幕共享」。
主界面顶部会显示「发送邀请中 → 待接收 → 正在连接 → 正在共享」，可直接取消邀请或结束共享；超时或失败时保留原因并提供重新共享入口。同一台电脑的未结束邀请不会重复发送。
接收方关闭观看窗口或点击结束，也会停止本次共享。拒绝邀请、连接超时和异常断线会自动结束采集。

视频使用 WebRTC，目标 30 fps、最高 8 Mbps，随网络和设备性能调整；不写入剪贴板或历史记录。
目前面向同一局域网的 Windows 电脑，不包含音频或远程键鼠控制。无需云端账号。
共享邀请沿用设备访问令牌，连接协商复用 ClipRelay 的 TCP 端口，视频通过 WebRTC 的动态端口传输。
对方旧版本会提示需要更新。断线后会结束会话，恢复网络后可重新发起。

安装脚本会安装固定版本的 Electron 视频引擎并核验下载校验值；离线包包含引擎时直接使用包内文件。
实现与开源调研见 [screen-share/RESEARCH.md](windows/screen-share/RESEARCH.md)。

## 电脑遥控手机翻页

手机进入历史记录的全屏预览后，点击 Windows 主窗口右上方的「手机翻页」，或在托盘图标右键菜单选择「手机翻页」，
选择手机，再点击「上一页 / 下一页」或在遥控窗口内按 `←` / `→`。手机的剪贴板广播开关不影响遥控。
遥控窗口显示手机实际的「当前页 / 总页数」和内容类型；手机手动滑动也会同步，每约 0.6 秒刷新一次。
电脑端按内容时间翻页：「上一页 / ←」查看更早内容（页码增大），「下一页 / →」查看更新内容（页码减小，例如第 2 页到第 1 页）。到最新内容时禁用「下一页」，到最早内容时禁用「上一页」；首尾不循环，文本和图片都支持。
手机切到后台或退出全屏后停止接收遥控，电脑清空页码并提示打开预览；重新打开不会补执行旧指令。
实时页码需要电脑端和手机端同时更新；旧版手机仍可翻页，窗口会提示更新手机端。请求只发送给所选设备，沿用设备的访问令牌。

协议为 `POST /preview/navigate`，JSON 为 `{"direction":"previous"}` 或 `{"direction":"next"}`。
协议方向沿用页码顺序：`previous` 减小页码，`next` 增大页码；Windows 将按时间定义的按钮方向映射到该协议。
`200` 表示指令已入队，`409` 表示手机不在前台全屏预览或队列已满；认证规则与 `/push` 相同。
`POST /preview/state`（JSON `{}`）返回实际阅读状态，例如 `{"active":true,"page":2,"pageCount":8,"contentType":"text","moving":false}`。
页码从 1 开始，类型为 `text` 或 `image`，`moving` 表示翻页动画进行中；未打开前台全屏预览时返回 `active:false`、页码及总数为 `0`、类型为 `null`。
状态接口同样需要设备认证，不返回剪贴板正文或图片内容；退出遥控窗口后停止查询。

## 旧版局域网兼容

新安装和升级均默认关闭旧版 HTTP 收发；原有设备地址、端口和密钥会保留。Windows 添加设备默认使用配对加密连接。仍需连接旧设备时，必须分别在发送端和接收端明确开启兼容：

- Windows：设备编辑中的「允许旧版未加密发送」只影响该目标；偏好设置中的「允许旧版未加密接收」只影响本机 HTTP 接收。设置自动保存。
- Android：接收设置中的「旧版局域网兼容（未加密）」保存后生效。关闭时不打开旧版监听端口，也不发布旧版 mDNS 地址；配对接收服务独立运行。
- Mac Electron：托盘菜单中的「旧版局域网收发（未加密）」控制收发。可设置本机接收密钥；设置后接收器会验证该密钥。配对加密连接独立运行；只有明确选择旧版目标时，发送快捷键才会使用该兼容路径。

兼容模式只允许回环、私有局域网和链路本地地址，不允许公网或共享地址段。发送端固定本次解析出的局域网 IP，拒绝 HTTP 重定向。访问密钥用于访问校验，文本、截图和密钥仍以明文传输。未开启兼容的目标会提示「兼容未开启」，不会自动降级发送。Windows 的屏幕邀请接口与配对远控服务独立于旧版剪贴板接收开关。

Mac 接收端新增请求大小、UTF-8、超时和连接数限制。相关 Windows/Android/Mac 协议与迁移测试通过；Mac App 构建和实际界面未在本机验证，用户暂不要求 Mac 真机验收。

## 注意

- 旧版兼容仅适用于可信内网，须在两端明确开启：HTTP 为明文。访问密钥可以阻止未授权的 ClipRelay 请求，但不能加密文本或截图；密钥留空时，同网段其他设备可以往你的剪贴板推入文本或图片，也可能看到传输中的截图。
- Windows 端每次用 `Ctrl+C` 复制的文本都会自动发给已开启且允许发送的对端。复制密码、令牌等敏感
  内容前，请先从系统托盘退出 ClipRelay；鼠标右键菜单复制和 `Ctrl+Shift+C` 不会触发发送。
- Mac 之间可以使用 `.local` 主机名，避免 DHCP 导致 IP 变化。
- 部分 Windows/Android 环境无法稳定解析 `.local`，此时请使用局域网 IP，并在路由器中配置 DHCP 静态租约。
- mDNS 标准使用 `224.0.0.251:5353`（IPv4）或 `ff02::fb:5353`（IPv6）组播，只在当前链路内工作；ClipRelay 当前从发现结果中选择 IPv4 作为发送地址。访客 Wi-Fi、AP 隔离、部分 VPN、防火墙或路由器的组播过滤会导致扫描不到；这不影响按 IP 手动配置。
- 首次使用如 macOS 防火墙弹窗询问 ClipRelay 是否接受传入连接，选择允许。
- Android 13 及以上版本可能显示系统自带的剪贴板浮层；应用无法可靠关闭这个系统提示。
- Windows 安装器创建的防火墙规则只允许“专用网络”；请勿为了使用本工具把公共网络改成专用网络。
